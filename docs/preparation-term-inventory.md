# 原准备输入的声明术语库存

本合同只读验证无前继、无该身份 run/采用/当前候选的 v1/v4 准备输入。
旧输入必须通过原冻结 scope（`current=False`）及完整原政策检查，origin 必须属于
accepted main 的祖先。以后授权扩范围不回写旧 scope。存在 scope/policy 错误时
不适用本合同；原有负结果诊断边界保持。

原 Git 的 `_qualified_declaration_parts` 必须匹配已知 SHA256
`46d7c3d8a2d0186a84af33365e22d0160394465a70e0a3ea498215f1157f1d80`。
`source_projection`、`source_inventory`、`_space`、`source_tex_hash`、`_matches`、
`_term_pattern`、`_literal_mailto_spans`、`_assignment_set` 的完整函数源字节必须
与当前加载实现相等。仅执行受审查的静态原声明函数及这些当前 reader，不执行
旧 Git 代码。使用完整冻结 units/catalog 重算所有记录，要求元数据、声明、术语、
位置、顺序和次数全部相等；未知旧函数、其他算法变化或不完整库存仍拒绝。

该读取继续完整来源 lowering、原 prompt/style/glossary、runtime/实际身份、原 raw
路径/hash/顺序/五字段和上下文检查，记录
`original_term_inventory.disposition=original-preparation-term-inventory` 与
`generation_validation=not_claimed`。有 raw 的完整或部分输出继续采用既有解析器；
本合同不创建成功生成、已验证失败 run、采用、历史或审批凭证。

不改写 unit、候选、run、raw、freeze 或原 model-input。当前候选术语、实际装配及
历史回放的 reader 保持当前实现。旧准备清单中 `of formal objects`、`at`、`along`、
`by` 等原字段仅为库存，不成为候选或术语批准。本工具独立验收、维护者批准、必需
CI 及合并后，具体章节才可在自己的数据任务中应用。
