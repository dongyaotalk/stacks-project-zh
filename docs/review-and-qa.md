# 审校与质量门禁

## 1. 角色分离

工作流包含以下角色：

- 调度者：冻结批次、来源和输入包；
- 模型译者：生成候选译文；
- 结构检查器：验证 LaTeX 和占位符；
- 术语检查器：验证词表和报告新术语；
- 独立批评者：查找语义错误，不重写全文；
- 语言审校者：确认中文表达和逐句对应；
- 数学审校者：确认数学含义、条件、方向和证明；
- 发布者：验证门禁并生成 release manifest。

同一人员可以承担语言和数学审校，但必须分别记录两种决定。任何模型或自动化工具
都不能填写人工审校者身份。

## 2. 风险等级

| 等级 | 典型内容 | 必须审校 |
|---|---|---|
| R0 | 标签、纯结构、生成元数据 | 自动结构检查 |
| R1 | 序言、介绍、历史和一般说明 | 人工语言审校 |
| R2 | 数学性例子、注记、练习、说明段落 | 语言审校 + 数学抽查或指定审校 |
| R3 | 定义、引理、命题、定理、推论、证明 | 语言审校 + 人工数学审校 |

解析器应根据节点类型给出默认等级。降级必须由人工在审校记录中说明；模型不能
降低风险等级。

## 3. 阶段授权

| 状态变化 | 授权者 |
|---|---|
| `UNTRANSLATED → AI_DRAFT` | 翻译器 |
| `AI_DRAFT → STRUCTURE_OK` | 确定性结构检查 |
| `STRUCTURE_OK → TERM_OK` | 术语检查；没有待决术语 |
| `TERM_OK → CRITIC_OK` | 规划中的批评门禁；当前无 Schema/命令，不得执行该提升 |
| `CRITIC_OK → LANGUAGE_REVIEWED` | 人工语言审校者 |
| `LANGUAGE_REVIEWED → MATH_REVIEWED` | 人工数学审校者 |
| 审校完成 → `PUBLISHED` | 发布门禁 |

任何候选内容变化都会使依赖其 hash 的旧审校失效，并退回相应阶段。

## 4. 自动 QA 层次

### 4.1 数据检查

- JSON/JSONL 可解析并符合版本化 Schema；
- 单元 ID 唯一且引用存在；
- 标题单元的 `parent_tag` 与其渲染标签在锁定 harvest `tags/tags` 中的永久 Tag
  完全一致；
- 每个批次至少有一个渲染标签存在于锁定 harvest 的对应章源文件中；累积预览按
  批次首个所属标签在源文件中的出现顺序装配，并保持批次内部 AST 顺序；
- 来源 commit 与 `upstream.lock` 一致；
- 候选记录包含 Harness、具体模型、model record、run ID、提示词、上下文和词表版本；
- 状态迁移合法。

### 4.2 结构检查

- 非自然语言 AST 节点完全一致；
- 公式 AST、标签、引用、引用键和环境结构一致；
- 占位符数量、类型和顺序一致；
- 没有新增未知命令或环境；
- 列表、表格和交叉引用可恢复。

### 4.3 语言和术语检查

- 已批准术语一致；
- 禁用译法没有出现；
- 未知术语进入待决队列；
- 每个数学术语的每次出现均为 `中文（English）`，记录数、重复次数和顺序一致；
- 没有异常英文残留、模型套话或正文外说明；
- 中文标点和空格符合风格规范。

### 4.4 语义批评

批评者逐条输出问题，字段包括 `unit_id`、严重性、类别、英文位置、中文位置、
理由和最小修订建议。不得只给分数，也不得重写整个单元。

本节当前是尚待实现的记录合同：仓库还没有 critic JSON Schema、`review/issues/`
事实目录或 `make critic` 命令，因此现有候选最高仅到 `TERM_OK`。在这些接口和测试
落地前，PR 可附人工 critic 摘要，但不能据此修改候选为 `CRITIC_OK`。

严重性：

- `blocker`：无法确定来源或结构，禁止继续；
- `critical`：数学含义可能错误，禁止提升；
- `major`：明显语义、术语或对应问题，必须修复；
- `minor`：不影响含义的语言问题；
- `note`：供人工确认，不自动阻断。

### 4.5 TeX 和 PDF 检查

- 日常翻译和候选 PR 默认以 XeLaTeX、BibTeX、makeindex 全流程无报错完成作为 PDF
  门禁；除非用户明确要求页面检查，不生成 PDF 页面截图，也不进行逐页或抽页目视验证；
- 候选预览没有未定义引用、引用键或重复标签；尚未译入的跨章 `\ref` 应显示为
  可点击的 `Tag XXXX（待译）`，且永久 Tag 必须来自锁定 harvest 的 `tags/tags`；
- 用户明确要求页面检查时，再确认目录、页眉、索引、中文字体、蓝色超链接、公式、
  图表和分页没有明显回归；
- 即使进行页面检查，不完整候选预览中的孤行、寡行或页尾留白也不属于翻译阻断；
  不得仅为改善此类临时分页而改写译文；
- PDF 元数据包含正确英文来源和翻译通道；
- 构建产物与当前 Git 状态可对应。

跨章占位文字只用于不完整候选预览，不代表引用已通过发布门禁。正式发布仍要求
所有内部引用目标均已译入并恢复为原始 `\ref` 跳转。

## 5. 人工语言审校

语言审校者必须同时查看英文、中文、占位符恢复预览和相关术语，检查：

- 信息是否逐项对应；
- 中文是否清楚、自然但不过度改写；
- 指代、逻辑连接和句间关系是否正确；
- 专名、引用和术语是否一致；
- 数学术语是否在每次出现时同时保留中英文，而不是只在首次出现时保留；
- 是否出现模型添加的解释或总结。

## 6. 人工数学审校

数学审校者必须核对：

- 定义域、值域、对象和态射方向；
- 假设、结论、必要/充分条件；
- 量词、否定、唯一性和存在性；
- 证明步骤之间的因果关系；
- 引用的定理是否支持当前推导；
- `respectively`、编号列表和多对象对应关系。

数学审校不是重新证明所有结果，但不能只根据中文流畅程度批准。

## 7. 失败和重试

- 结构或占位符失败：拒绝候选，重新生成，不做文本级猜测修复；
- 术语待决：暂停受影响单元，先走术语 PR；
- critical/major 语义问题：由修订任务做最小修改，再重新运行全部依赖门禁；
- TeX 失败：区分翻译数据、渲染器和模板问题，禁止直接修改生成 TeX 规避；
- 来源在任务中变化：废弃当前批次并按锁定版本重新排队；
- 连续失败：保留尝试和错误报告，交由人工决定，不无限自动重试。

## 8. PR 必备审查材料

翻译或审校 PR 至少包含：

- 英文来源 commit；
- Section/Tag 和单元列表；
- 模型与提示词版本；
- 双语逐单元 diff；
- 结构、术语和构建摘要，以及人工提供的批评状态；
- 新术语或待决问题；
- 语言/数学审校状态；
- 对应 PDF 预览位置或 CI 产物。

整章或整书的大型 PR 不符合审查粒度，应拆成 Section。
