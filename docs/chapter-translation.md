# 章节候选翻译的默认执行规则

本规则适用于“翻译第 N 章”“补齐某章候选”等请求。用户只需指定目标章节，
无需重新提供执行清单。按锁定目录解析章号与 slug；只有无法唯一确定范围或缺少
必要授权时才询问。用户本次明确要求优先于默认规则。

## 目标与任务边界

默认目标是补齐指定章的完整来源候选，保留既有合格成果。候选完成不包含人工语言
审校、数学审校、术语批准或正式发布；不得制造这些状态。`next-task` 因已有候选
返回 `REVIEW` 时，继续检查指定章尚未覆盖的来源，不把它当作停止候选工作的理由。

先一次只读核实 fresh main、分支、未提交改动、打开的 PR、claimed Issue、来源锁和
范围冲突。复用当前任务及有效准备材料，不重开旧任务，不应用或删除无关 stash。

用户明确指定整章，即按一个集中候选任务准备一个精确 `scope_manifest`；获得对应
GitHub 写入授权时，使用一个 Issue、一个数据分支和一个最终数据 PR。其多个
data scope 各自保持明确的完整来源范围和唯一文件所有权，继续满足
`config/workflow.yml` 的 `one_section_or_contiguous_units`；章节是协调范围，不是
把整章合并成一个不分范围的模型输入。仍须遵守当前 main 已接受的清单/hash、Issue 认领及原生
closing relation 合同。范围变化先更新同一清单和 Issue，再冻结新的生成输入；
已经冻结的输入不回写。外部创建、推送及合并按用户实际授权执行，规则不授予平台权限。

同一章节候选任务保持同一模型 lane、Harness 和具体模型；多个模型包可有多个真实
run，每个包独立冻结、独立记录身份并完整溯源。比较或切换模型另行声明任务。
这是对精确范围清单模式的章节候选用途说明，旧内联 Issue 的单 run、单章及
2–8 Tags 限制保持；不能只凭“整章”字样绕过范围、来源或远端门禁。

## 已实现的整章来源预检

生成前可先运行 `chapter-preflight --root . --harvest ../stacks-project --chapter <章号或slug>`，
一次准备完整来源 selector、原生 Tag 覆盖、阻断和有序包/文件所有权提案。入口和恢复
用法见 [整章预检与恢复](chapter-preflight.md)。READY 仅表示来源能力，候选/人审完成
分别报告；它不替代实际任务范围、生成冻结、来源采用、完整 QA 或发布权限。

## 先收敛前置，再连续生成

1. 复用锁定 Git 全库抽取库存及统一队列，核对 source/config/input hashes。
   已有可信通过证据且输入未变时，不重新扫描全库，更不为每个 unit 重建库存。
2. 一次列清整章缺失的完整容器、READY/BLOCKED 原因、真实 selector、预计模型包和
   所需采用合同。READY 不是事实采用或译文完成；采用前仍核验完整源字节与边界。
3. 先用最小复现核实前置缺陷，并用针对性回归收敛实现。确有缺口才开独立最小
   工具或政策任务；相同责任的缺口在一个有明确范围的任务中集中处理。
   保持工具、政策、数据的任务边界，不提前为每个猜测启动整套验收。
4. 不依赖阻断的完整范围继续批量生成。模型包遵守现有2–8输入文件、同章相邻、
   语义完整及300–1500来源词偏好；合法的不可分割例外明确记录，不凑入无关文本。
5. 每次实际生成冻结完整 unit、全部必要旧组/历史、政策、提示词及真实邻近/引用
   上下文。动态解析 Harness，记录当次实际 model/turn/effort/run，不复制旧身份。
   模型生成完整五字段，程序只保护、验证、序列化和装配；失败及重试原输出全部保留。

不自动把普通来源改成 notation，不降低未知宏、数学文字、token、术语或溯源门禁。
工具已有合法入口时优先复用，不为单章翻译顺带重构工具或增加新的历史格式。

## 开发期只检查本次变化

每包核验完整来源、五字段与 raw/context/history 绑定、逐次术语、保护 token 原序/
次数/尾空白、ID 和范围外字节。优先用现有 `validate`、`qa-batch`、`render-batch`
定位问题；调用前核实参数，不混合不同真实 run 的单次 run 接口。

这些入口按需要选择，不是每包依次运行的清单。`render-batch` 已包含批量 QA，
需要渲染时直接调用，不先额外运行同一 `qa-batch`。只定位当前候选问题时用默认
严格 `validate`；适用 QA/render 入口的来源和完整历史检查保持，最终 `qa-all`
集中覆盖全部 lane 和全部真实 run。不要把不同 run 交给单 run 的批量入口。

按需使用实际候选 lane 的 `pdf-chapter` 作章级编译预览；不每包构建整书、提交、
推送、创建 PR 或同步进度。没有新失败、输入变化或未解决疑点，不重复已通过检查。

术语检索结果只是检查线索，必须按完整来源语境判断。一般方位、赋值动词和普通
语言措辞不能只因词表命中就当作数学术语缺陷；复合词已有有效分解覆盖时不重复
要求整词。不得在翻译中新增政策、机械补中文或无证据扩大重译范围。确有遗漏按
已接受合同冻结完整批次并实际模型重译，不改旧 raw/run，不继承批准。

## 阶段末集中验收

实现及本包检查稳定后，每个独立任务执行一次适用的最终验收。失败先定位并修复
责任范围，再复核受影响证据；不要在实现仍变化时不断启动整套构建。

- `qa-all` 已包含 Schema、完整递归溯源、决策和全部当前候选 QA，以及工作流、
  harvest、upstream index 和全部章节模板检查；同轮通过后不再逐条重复这些子命令。
  独立命令用于失败定位。真实新 run 及来源/术语/证明检查按适用合同完成。
- 工具有改动才运行相应开发回归；不为纯候选或文档写与实现同义的测试。
  最终适用工具测试及远端必需 CI 保持。输入未变的已通过证据可绑定复用，不能
  将旧结果改称本次运行，不能伪造成功缓存或以局部检查代替必需最终门禁。
- 提交/PR 前实际运行相应 lane 的 `make render` 和 `make pdf`。候选编译实际含有
  本次候选的 lane；仓库另要求集成 lane 时一并执行。模板、样式、Makefile 或
  渲染路径改变时才追加 `make template`。每条 Make 显式使用已核实的 Python3.12。
- 排版验收默认仅要求 LaTeX 编译零退出及最终日志门禁通过，包括缺字、未定义
  引用/引用键和重复标签检查。不生成截图/PNG，不做逐页或抽页视觉检查，也不为
  此追加 PDF 全文或像素比较。仅用户明确提出页面检查时执行相应额外要求。
- 提交前审查完整 staged diff；PR 保留精确范围、head/base 原字节及完整 patch、
  真实必需 CI 和 fresh main 门禁。无授权不自行 bypass、发布或更改保护规则。

同一章候选数据合并后，只做一次独立 progress/plan 任务：实际生成并执行对应
check，即使报告无变化也记录真实结果；不逐包重复。汇报候选、阻断和审校状态，
不把构建成功称为数学、语言或页面审查完成。

## 证据最小记录

保留命令、实际退出状态、检查所绑定的 commit/输入 hash、run、最终日志及证据
位置。输入未变的可信证据直接引用；变化时说明失效范围并更新必要检查。
每次更新说明实测进展、剩余具体阻断和下一动作，不重复长计划，不猜工期或百分比。
生成物、截图、本机路径及凭据不提交。
